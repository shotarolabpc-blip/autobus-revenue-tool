# data_build（配信データの加工）

都道府県コード（JIS X 0401、2桁）を指定して、`public/data/` に配信用データを作ります。
東京都専用の処理はありません。ほかの都道府県もコードを変えるだけで作れます。

## 準備（初回だけ）

プロジェクトのフォルダで実行します。

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r data_build\requirements.txt
```

## 人口・バス停・バス路線・市区町村（P0-4）

```powershell
.venv\Scripts\python data_build\build_prefecture.py 13
```

- 複数の都道府県をまとめて作る場合：`build_prefecture.py 13 14 11`
- 元データは `data_raw/ksj/` に置きます。無ければ自動で取得します（ログインや規約への同意は不要）。
  自動取得したくない場合は `--no-download` を付け、下の表のファイルを手で置いてください。
- 実行の最後に、生成したファイルの容量を表示します。

### 元データ（国土数値情報、CC BY 4.0）

`{pref}` は都道府県コード（例：13）に置き換えます。

| データ                                     | 版                           | 入手先                                                            | data_raw/ksj/ に置くファイル        |
| ------------------------------------------ | ---------------------------- | ----------------------------------------------------------------- | ----------------------------------- |
| 500mメッシュ別将来推計人口（R6国政局推計） | m500r6-24                    | https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-mesh500r6.html | `500m_mesh_2024_{pref}_GEOJSON.zip` |
| バス停留所                                 | P11-2022                     | https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-P11-2022.html  | `P11-22_{pref}_SHP.zip`             |
| バスルート                                 | N07-2022                     | https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N07-2022.html  | `N07-22_{pref}_SHP.zip`             |
| 行政区域                                   | N03-2026（2026年1月1日時点） | https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2026.html  | `N03-20260101_{pref}_GML.zip`       |

- バス停留所は **2022年度版** を使います（2010年度版は非商用ライセンスのため使いません）。
- 2022年度版のバス停は、同じ道路上の同じ事業者・同じ名称のバス停（上下線など）を1点にまとめています。
- バスルート（2022年度版）には便数（運行頻度）の項目がありません。

### 出力

| ファイル                                           | 内容                               | 形式を選んだ理由                                                                                                                                                     |
| -------------------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `public/data/population/{pref}/index.json`         | 年次・年齢階層・2次メッシュ一覧    | −                                                                                                                                                                    |
| `public/data/population/{pref}/{2次メッシュ}.json` | 集計単位ごとの年次×7区分の人口     | 表示範囲の2次メッシュ（約10km四方）のファイルだけを読めば済む。メッシュの形はコードから計算できるため座標を持たず、FlatGeobuf より小さく、特別な読込ライブラリも不要 |
| `public/data/busstops/{pref}.geojson`              | バス停名・事業者・バス区分・系統名 | MapLibre がそのまま表示できる                                                                                                                                        |
| `public/data/busroutes/{pref}.geojson`             | 事業者・備考（線形は約2mで簡略化） | 同上                                                                                                                                                                 |
| `public/data/municipalities/{pref}.json`           | 市区町村コードと名称               | 対象自治体の選択に使う                                                                                                                                               |

あわせて `public/data/prefectures.json`（初期表示範囲・データ整備済みか）と
`public/data/attributions.json`（国土数値情報の出典）を更新します。

### 人口の加工ルール（要件 5.2）

- 男女計の5歳階級（0〜4歳 … 95歳以上）を、全国都市交通特性調査の年齢区分に合わせた7区分「0-4／5-14／15-29／30-49／50-64／65-74／75+」に集約します（Q3：B）。要件定義書の4階層は、画面の表示用にこの7区分から合算します。
- 年次は 2025〜2070年の5年刻みです（2020年は年齢別の値がないため使いません）。年次の間はブラウザ側で線形補間します。
- 秘匿メッシュ（`HITOKU`＝`*`）の人口は、合算先メッシュ（`@`）に含まれています。
  どの年次でも合算関係にあるメッシュは、まとめて1つの「集計単位」とし、人口は構成メッシュの合計とします（秘匿メッシュは0人なので二重計上になりません）。
  面積按分では、集計単位の人口が構成メッシュ全体に一様に分布するとみなします。
- 7区分の合計が元データの総数（`PT00`）と一致することを検算しています。

## 注意

- `data_raw/` は Git の管理対象外です（元データは再配布しません）。

## 道路網タイル（P0-5）

```powershell
.venv\Scripts\python data_build\build_roads.py 13
```

- 元データ：Geofabrik が配布する OpenStreetMap の地域ファイル（例：`kanto-latest.osm.pbf`、約500MB）。
  `data_raw/osm/` に無ければ自動で取得します（ログイン・同意は不要）。都道府県と地域の対応は `osm_regions.yaml`。
- 範囲：都道府県の境界（国土数値情報 行政区域）に `boundary_margin_km`（初期値5km）の余白を付けた範囲。
  県境をまたぐ経路は、この余白の範囲まで計算できます。
- 採用する道路：`road_rules.yaml`（**初期案。確認待ち**）。バスが通れる道路だけを残し、一方通行（oneway）を反映します。
- 交差点間を1本の辺にまとめた有向グラフを、`tile_size_deg`（初期値0.05度、約5km）四方のタイルに分けて
  `public/data/roads/{県コード}/{tx}_{ty}.bin.gz` に出力します（gzip 圧縮した独自のバイナリ形式。形式は `roadgraph.py` に記載）。
- 関東全域の点の座標をすべてメモリに持たないよう、「道路の絞り込み → 必要な点だけ座標を読む」の2段階で処理します。
- pyosmium は全角文字を含む絶対パスを開けないため、`data_raw/osm/` に移動して相対パスで読みます。

### GitHub Actions で実行する

`.github/workflows/build-data.yml`：

- 手動：Actions タブ →「Build data」→「Run workflow」。都道府県コード（空なら整備済みすべて）と対象（roads／ksj／all）を指定。
- 定期：四半期ごと（1・4・7・10月の2日 3:00 JST）に、整備済みの都道府県の道路網を最新の OSM で作り直します。
- 生成したデータをコミットし、公開（deploy.yml）を起動し直します。

### OpenStreetMap のライセンス（ODbL）への準拠

- 画面の地図と出力物に「© OpenStreetMap contributors」を表示します（`public/data/attributions.json`）。
- 加工した道路網データ（派生データベース）は、`public/data/roads/` で ODbL の下に公開します（`LICENSE.txt`）。
  作成手順（このスクリプトと `road_rules.yaml`）も公開リポジトリで公開しています。

## 運賃の参考データの年1回の見直し（F-4A）

運賃の目安（標準・高め）に使う参考データ `public/data/fare_references.json` は、**年に1回**見直します。
確認日（`checkedAt`）から1年以上たった値は、画面で「古い可能性があります」と表示されます。

### 手順

1. `data_build/fare_references_source.py` を開く（値・出典URL・確認日がすべてここに書いてある）。
2. 下の「確認する資料」の各ページを開き、運賃が変わっていないか確認する。変わっていれば、`flat` / `base` / `rate` と `note` を直す。
   **公式の資料に載っている値だけを書く。推測で補わない。**確認できなかった項目は削除し、`NOT_FOUND` に理由を書く。
3. 確認した項目の確認日を更新する：`CHECKED_AT` を今日の日付に変える（確認していない項目は、項目ごとの `src(...)` に日付を直接指定して古いままにする）。
4. 新しい事業者・コミュニティバス・自動運転バスを足す場合は、**種別（`category`）を次の基準で決める**（2026-10-15 決定）：
   - `route`＝路線バス：事業者が一般乗合旅客自動車運送事業として運行する通常の路線（国土交通省・関東運輸局の認可・届出資料、事業者・都交通局の運賃表）。
   - `community`＝コミュニティバス：**自治体が運行主体、または委託・補助して運行しているバス**（自治体の公式資料で確認できるもの）。
     呼び方は「循環バス」「ムーバス」などでもよい。**運行主体・委託・補助が書かれた公式ページのURLと、その文言を `categoryBasis` に必ず残す**。
   - `autonomous`＝自動運転バス：資料に「自動運転バス」と書かれているもの。
   - 運行主体を公式資料で確認できないものは、推測で分類せず載せない（`NOT_FOUND` に理由を書く）。
   - 根拠が間接的な場合（例：台東区「めぐりん」）は、その旨を `categoryBasis` と `note` に書く。
5. **コミュニティバスの参考データを当てはめる地域の単位**（`cityCodes`）は、次のとおり（2026-10-15 決定）：
   - 区が運行するバス → **区部（23区）の全区**で参考にする（`WARDS`）。
   - 市が運行するバス → **市部（東京都の26市）の全市**で参考にする（`CITIES`）。
   - 理由：運行環境（人口密度・路線バスの密度）が近い単位で、市区町村ごとに分けると、データのない市区町村が増えるため。
   - 町村・島しょのコミュニティバスの参考データは、まだ載せていない（その地域では、路線バスなど、データのある種別が強調される）。
   - 自動運転バスは事例が少ないため、都内全域で参考にする（`cityCodes` は `None`）。
6. 実行する：

   ```powershell
   .venv\Scripts\python data_build\fare_references_source.py
   .venv\Scripts\python -m pytest -q data_build\tests
   npm test
   ```

7. 差分を確認して、コミットする。

### 確認する資料

| 種類                           | 確認先                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 都営バス                       | 東京都オープンデータ「バス 普通運賃」（`bus_fare_ordinary_fare.csv`）、東京都交通局の運賃のページ             |
| 民営バス（実施運賃・上限運賃） | 関東運輸局の「乗合バスの運賃改定」の公示・報道発表（`wwwtb.mlit.go.jp/kanto/`）、各事業者の運賃改定のお知らせ |
| 制度の一覧                     | 関東運輸局「管内都県別乗合バス運賃制度一覧」（毎年4月ごろ更新）                                               |
| コミュニティバス               | 各区市の公式サイトの運賃のページ（`fare_references_source.py` の URL）                                        |
| 自動運転バス                   | 運行事業者・自治体の公式ページ                                                                                |

### 他の地域に広げるとき

参考データは都道府県コード（`prefCode`）で持ち、地域専用の分岐はありません。ほかの道府県は、同じ形式で項目を足します。
データがない地域では、画面は目安を出さず（理由を表示）、上限運賃を手入力できます。

## 祝日データ（`build_holidays.py`）

内閣府は、毎年2月ごろに翌年の祝日を公表します。公表された年は「推定」でなくなり、公表前の年だけが推定値になります。

```powershell
.venv\Scripts\python data_build\build_holidays.py --refresh
```

`--refresh` を付けると、内閣府の CSV を取り直します。GitHub Actions の「Build data」の定期実行（四半期ごと）でも、
自動で実行します。
