# Claude Code 依頼プロンプト集（要件定義書 v0.5 対応）

## 使い方
- **上から順に1つずつ**依頼する。1つ終わるごとに画面で確認し、問題なければコミットする。
- 依頼の切れ目で `/clear` して会話をリセットすると、Claude Codeが前の作業内容に引っ張られにくくなる。
- 大きな依頼は、まずプランモード（Shift+Tab）で計画だけ出させ、内容を確認してから実装させる。
- うまくいかないときは「範囲を狭める」（例：東京都 → 東京23区）。

---

## 0. 事前準備（自分で行う作業）
1. GitHubで**公開リポジトリ**を作る（無料プランでPagesを使うため。公開してよいか上長確認済みであること）。
2. 手元にクローンし、以下を置く。
   - `docs/requirements.md` … 要件定義書 v0.5 の中身
   - `CLAUDE.md` … 同梱の CLAUDE.md
3. リポジトリの Settings → Pages → Source を **GitHub Actions** にする。
4. 手元のPCに Node.js（LTS）、Python 3.11以上、Git を入れておく。

### P0-4 人口・バス停・バス路線データの加工（東京都）
```
data_build/ に、都道府県コードを引数にとって配信用データを作る Python スクリプトを作ってください。まず東京都（13）で動かします。

対象データ（国土数値情報）：
- 500mメッシュ別将来推計人口（R6国政局推計）
- バス停留所（2022年度版。2010年度版は非商用ライセンスなので使わない）
- バスルート

要件：
- 元データは data_raw/ に私が手で置く前提にし、必要なファイル名と入手先URLを README に書く（自動ダウンロードできるものは自動でも可）。
- 人口は男女・5歳階級を「0-14／15-64／65-74／75+」の4階層に集約。秘匿・合算先メッシュは合算先とまとめる。
- 出力は public/data/population/{県コード}.*、public/data/busstops/{県コード}.geojson、public/data/busroutes/{県コード}.geojson。
  形式は、ブラウザで表示範囲だけ読める形式（FlatGeobuf など）を提案して選んでください。
- 必要な属性だけ残して容量を減らす。生成後に各ファイルの容量を表示する。
- 地図に「既存バス停」「既存バス路線」「人口メッシュ」の表示切替レイヤを追加し、
  2022年度版のバス停は上下の停留所を1点にまとめている旨の注記を出す（F-2-2）。
- 出典（国土数値情報、CC BY 4.0）を attributions.json に追加。
```

### P0-5 道路網タイルの生成（東京都）
```
要件 F-2-5c・F-2-5f と「6. 推奨技術構成」の経路生成・道路網の加工を実装します。まずデータ生成側です。

- 入力：Geofabrik の日本の関東地方の OSM データ（.osm.pbf）。
- 都道府県の境界（国土数値情報の行政区域、または OSM の境界）で切り出し、県境をまたぐ経路に備えて境界の外側に数km の余白を含める。
- バスが通れる道路だけ残す。道路種別の採否・アクセス制限（access, motor_vehicle, bus, psv）の扱いは
  data_build/road_rules.yaml に設定として持たせ、初期案を提示して私に確認してください。
- 一方通行（oneway）を反映し、交差点間を1本の辺に簡略化した有向グラフを作る。
- 経路計算用に、グラフを格子状のタイルに分割したバイナリ形式で public/data/roads/{県コード}/ に出力。
  1ファイル100MB未満、gzip 前提で、なるべく小さく。表示用の線形も保持して、経路の線を道路に沿って描けるようにする。
- この処理を GitHub Actions のワークフローとして実行できるようにする（手動実行＋四半期ごとの定期実行）。
- 生成後の合計容量を表示する。
- 出典「© OpenStreetMap contributors」と ODbL への準拠方法を attributions.json と README に追加。
```

### P0-6 ブラウザ内経路計算
```
P0-5 の道路網タイルを使って、ブラウザ内の経路計算を実装してください（src/routing/）。

- Web Worker で動かし、画面を固まらせない。
- 2点間の経路を双方向A*（または同等の手法）で計算。必要な範囲のタイルだけを読み込み、読み込んだタイルはキャッシュする。
- 地図上で2点をクリックすると、道路に沿った経路と距離（km）が表示される確認用の画面を作る。
- 点は最寄りの道路に自動で寄せ（スナップ）、寄せた距離が大きいときは警告。
- 経路が見つからない場合は「直線でつなぐ」に切り替えられるようにする。
- 小さなテスト用グラフで、最短経路と一方通行のテストを書く。
- 東京都内で 1km／5km／20km の経路計算にかかる時間を計測して報告。
```

## Phase1（MVP）：機能の実装

### P1-1 ルート・バス停編集
```
要件 F-2（F-2-3〜F-2-11、F-2-5a〜F-2-5f）を実装してください。

- 既存バス停をクリックで採用、地図クリックで新規追加、移動、削除、名称変更。
- バス停は登録順につなぐ。一覧のドラッグ＆ドロップと上下ボタンで並べ替えでき、影響する区間だけ再計算。
- ルート線をドラッグすると経由点を追加でき、通したい道路に寄せられる（経由点はバス停として扱わない）。経由点の削除も可。
- 区間ごとに「自動／直線／手描き」を切り替え可能。
- 循環／往復の指定。循環は最後のバス停から最初のバス停まで自動でつなぐ。
- ルート総延長とバス停間距離を表示（手修正可）。
- 勢圏円（初期300m、500m も選択可）の表示。
- ルート・バス停の GeoJSON／CSV 入出力。
- 編集内容はプロジェクトファイルに保存され、読込で復元されること。
```

### P1-2 運行計画と車両の前提条件
```
要件 F-3（F-3-1〜F-3-4）と F-3A（F-3A-1〜F-3A-5、F-3A-7）を実装してください。

- 車両プリセットは public/data/vehicle_presets.json で管理し、要件定義書 F-3A の表の4車種＋カスタムを入れる。
  各値に出典を持たせる。表にない項目（航続距離など）は、出典が要件定義書にあるものだけ入れ、
  ないものは空欄にして「要入力」と表示する（数値を推測で入れない）。
- 実効定員＝運用定員−保安要員の人数、輸送力＝実効定員×便数×最大乗車率（初期100%）。
- 年間運行日数は、対象年度の実際のカレンダー（内閣府の国民の祝日データ）から平日／土休日を自動計算。
  祝日データは data_build で public/data/holidays.json に変換。年末年始運休の有無はユーザー設定。
- 所要時間＝ルート延長÷平均速度（手修正可）。航続距離・充電時間から1台の1日最大便数の目安を出し、超えたら警告。
- ユーザー定義プリセットをプロジェクトファイルに保存。
```

### P1-3 運賃設計
```
要件 F-4（F-4-1〜F-4-3、F-4-5、F-4-6）を実装してください。

- 運賃制度区分（実施運賃／協議運賃）の選択（計算には使わず出力に記載）。
- 均一制：1乗車の運賃。
- 対キロ区間制：初乗り運賃＋賃率×区間キロ、端数処理（10円単位の切上げ・四捨五入・切捨て）を選択。
- バス停間の運賃表（三角表）を自動生成し、セル単位で手修正できる。
- 割引区分（小児・高齢者・障がい者・定期・回数券・無料パス等）ごとに構成比と割引率を入力し、実効平均運賃を計算。
- 運賃は税込で入力し、税抜換算（標準税率10%）も持つ。
- src/calc/fare.ts に純粋関数で実装し、手計算で確かめられるテストを書く。
```

### P1-4 需要推計の係数データ
```
要件 5.1A と付録B に従い、需要推計の係数データを作ります。

- 全国都市交通特性調査（令和3年）の集計データから、

```

### P1-5 需要推計の計算
```
要件 F-5（5.1、5.2、5.3、5.5）の計算を src/calc/demand.ts と src/gis/ に実装してください。

- 勢圏（円）とメッシュ人口の面積按分で、バス停ごと・年齢階層ごとの勢圏人口を出す。勢圏が重なる部分は二重計上しない。
- 5年刻みの人口推計を年次で線形補間する。
- 5.1 の式で年度別の年間利用者数を計算する。各項（人口・外出率・トリップ数・分担率・捕捉率・補正係数・運行日数）を
  内訳として返し、画面で「なぜこの人数か」を確認できるようにする。
- 路線捕捉率：既存バス路線と勢圏が重なる場合は便数比で按分、重ならない場合は1.0（既存路線の便数が不明な場合の扱いは私に確認）。
- 開発計画（地点 or メッシュ、開始年度、人数、段階入居年数、年齢構成）、エリア全体の人口補正率、施設需要の手入力。
- 輸送力を超える需要は輸送力で頭打ちにし、警告を出す。
- 最初に「バス停3つ・メッシュ2つ」の手計算できるサンプルと期待値を tests/fixtures に作り、
  そのテストが通ってから画面に組み込む。サンプルの期待値は私が確認するので、計算過程も一緒に出してください。
```
