## 見積りの方法と計算式

### 国土数値情報（人口・バス停・バス路線）

都道府県 *p* の生成データの容量は、元データ（国土数値情報の zip）の大きさに比例すると仮定します。

> 容量(*p*) ＝ 元データの大きさ(*p*) × 〔東京都の生成データ ÷ 東京都の元データ〕

元データの大きさは、ファイルを取得せずに Content-Length で47都道府県分を調べました。

| データ | 比（生成÷元） | 全国の見積り | 大きい都道府県（1ファイル） |
|---|---|---|---|
| 人口メッシュ（7区分。Q3：B） | 0.205 | 約144 MB（4区分の約1.3倍） | 北海道 6.5 MB（2次メッシュ単位に分割するので1ファイルは数十KB） |
| 既存バス停 | 1.557 | 67.8 MB | 北海道 3.3 MB、東京都 2.9 MB |
| 既存バス路線 | 0.951 | 134.4 MB | 鹿児島県 6.2 MB、北海道 5.2 MB |
| **小計** | | **312.0 MB** | |

### 道路網

道路網は、OpenStreetMap の地域ファイル（Geofabrik）の大きさに比例すると仮定します。

1. 東京都（県境＋5km の余白を含む）で採用した道路は 244,231 本で、関東の地域ファイル全体の採用候補 1,112,488 本の **21.95%**。
2. 関東全体（各都県が余白を含めて作る分の合計）≒ 東京都の道路網 10.62 MB ÷ 0.2195 ≒ **48.4 MB**
3. 全国 ≒ 関東 × 〔全国の地域ファイルの合計 2,528 MB ÷ 関東 518 MB〕≒ **236.1 MB**

| 地域ファイル | 大きさ |
|---|---|
| 北海道 | 190 MB |
| 東北 | 310 MB |
| 関東 | 518 MB |
| 中部 | 512 MB |
| 関西 | 353 MB |
| 中国 | 239 MB |
| 四国 | 90 MB |
| 九州（沖縄を含む） | 316 MB |
| 合計 | 2,528 MB |

1タイルは最大 184 KB（東京都の実測）。地方は道路が疎なので、これより小さくなる見込みです。

### 合計

| データ | 見積り |
|---|---|
| 国土数値情報（人口・バス停・バス路線） | 312 MB |
| 道路網 | 236 MB |
| アプリ本体・共通データ | 3 MB |
| **合計** | **約 550 MB** |

### 見積りの幅（不確かさ）

- 道路網：地域ファイルには建物などの道路以外のデータも含まれ、その割合は地域で異なります（都市部は建物が多い）。地方では「ファイルの大きさあたりの道路」が多い可能性があり、**道路網は最大で1.5倍程度（約350MB）**になることを見込みます。
- 国土数値情報：元データと生成データの比は、属性の量（バス停の系統数など）で変わります。±20% 程度を見込みます。
- 以上から、全国の合計は **約 450〜700 MB** とみます。1 GB には収まる見込みですが、余裕は大きくありません。

## 注意点：リポジトリの履歴が増え続ける

GitHub Pages の「公開サイト1GB」とは別に、**リポジトリ（Git の履歴）にも推奨上限**があります（1GB 未満を推奨、5GB を強く推奨）。
今の作りでは、生成データを `main` ブランチにコミットしています。道路網は四半期ごとに作り直すため、

- 全国展開後は、更新のたびに約240MBのバイナリが履歴に追加され、**1年で約1GB**ずつ増えます。
- 履歴は削除しない限り減らず、clone も遅くなります。

## 対策案（確認事項 Q9：案 C に決定。ただし、実施は全国展開の前でよい）

**決定（2026-10-15）**：案 C（データ用の別ブランチを毎回作り直す）を採用する。いまの公開データは東京都だけ（約22MB）で、履歴の増え方は小さいため、**実施は、東京都以外のデータを公開する前（目安：公開データが300MBを超える前）**とする。それまでは、いまの作り（生成データを main にコミット）のままにする。

| 案 | 内容 | 公開サイトの容量 | リポジトリの増加 | 手間 | 費用 |
|---|---|---|---|---|---|
| A. 今のまま | 生成データを main にコミット | 約550MB | 年 約1GB（全国） | なし | 0円 |
| B. データは Actions で作って直接公開 | 生成データはコミットせず、「Build data」で作ったデータを Pages の公開物に直接入れる（前回分は Actions のキャッシュ等から再利用） | 約550MB | ほぼ増えない | 中（ワークフローの組み直し） | 0円 |
| C. データ用の別ブランチを毎回作り直す | 生成データを `data` ブランチに「履歴なし」で上書き保存し、公開時に合わせる | 約550MB | ほぼ増えない | 小〜中 | 0円 |
| D. さらに圧縮 | バス停・路線を GeoJSON から独自形式（座標の整数化・差分）へ、人口の小数を1桁に | 約350〜400MB（見込み） | A〜C と組み合わせ | 中 | 0円 |
| E. 地域ごとに別リポジトリ | 東日本・西日本などで別の Pages に分ける（要件 5.6） | 1サイトあたり約300MB | 分散される | 大（URL・設定が増える） | 0円 |

おすすめ：**案 C（またはB）＋必要に応じて案 D**。全国分でも1GBに収まる見込みなので、案 E（分割）は今は不要と考えます。

## 参考：帯域

GitHub Pages の帯域の目安は月100GBです。1回の利用で読み込むのは、表示範囲の人口・道路網タイルと、その都道府県のバス停・路線（数MB〜十数MB）です。社内利用の規模では問題にならない見込みです。
