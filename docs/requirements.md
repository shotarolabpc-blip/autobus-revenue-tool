## 1. 目的・背景

### 1.1 目的
自動運転バス案件において、**ルート・バス停・運賃・運行計画・人口データ**をもとに、**年度別の運賃収入（利用者数×運賃）をロジカルに推計**し、根拠付きでエクスポートできる簡易Webツールを構築する。

### 1.2 本ツールで解決したいこと
- 「なぜこの利用者数になるのか」を**計算式・前提・データ出典つき**で説明できる
- ルート案・運賃案・運行本数案を**シナリオ比較**できる
- 人口減少・開発計画（人口増）を年次で反映できる
- 推計値を**公開されている既存路線の実績値と比較**し、桁感が妥当か確認できる
- 社内稟議・自治体協議資料にそのまま使える形式で出力できる

### 1.3 スコープ
| 区分 | 内容 |
|---|---|
| **Step1（本書）** | 収入予測（運賃収入＋その他収入の手入力） |
| Step2（将来） | 費用計画（車両・遠隔監視・保険・人件費・保守等）、収支・損益分岐、無料実証→有償化の年度設定 |
| Step3（将来） | 補助金反映後の自治体負担額試算、複数路線のネットワーク評価 |

> Step2以降を見据え、プロジェクトファイルは「収入」と「費用」を同一の年度軸で持てる構造にしておく（`costs` ブロックを予約）。

## 3. 全体の処理フロー

```
[新規作成] or [プロジェクトファイル読込]
      ↓
①エリア・ルート・バス停設定
      ↓
②運行計画設定（運行日数・本数・車両定員）
      ↓
③運賃設計（制定形態・運賃額・割引）
      ↓
④需要推計（人口×外出率×バス分担率×補正係数 → 年度別利用者数）
      ↓
⑤収入計算（利用者数×実効運賃＋その他収入）
      ↓
⑥参考実績との比較・シナリオ比較
      ↓
⑦エクスポート（プロジェクトファイル / CSV / Excel / PNG）
```

### F-4 運賃設計
国内の乗合バス運賃は道路運送法に基づき、主に以下の枠組みで定められる。ツールではこれらを選択・入力できるようにする。
- **上限運賃（認可）＋実施運賃（届出）**、または**協議運賃（協議会で協議が調ったうえで届出）**
- **制定形態**：対キロ区間制・特殊区間制・均一制・地帯制

| ID | 要件 | 優先度 |
|---|---|---|
| F-4-1 | 運賃制度区分の選択（実施運賃／協議運賃）※計算には影響しない。出力物に記載 | MVP |
| F-4-2 | 制定形態：**均一制**（1乗車○円） | MVP |
| F-4-3 | 制定形態：**対キロ区間制**（初乗り運賃＋賃率×区間キロ、端数処理ルール指定） | MVP |
| F-4-4 | 制定形態：**地帯制／特殊区間制**（ゾーン・区間ごとの運賃表を手入力） | Phase2 |
| F-4-5 | バス停間の**運賃表（三角表）を自動生成・表示・手修正** | MVP |
| F-4-6 | 割引設定：小児・高齢者・障がい者・定期券・回数券・無料パス等。区分ごとの**利用者構成比**と割引率を入力 | MVP |
| F-4-7 | 年度ごとの運賃改定（例：N年目に○円へ改定） | Phase2 |
| F-4-8 | 上限運賃（入力値）を超える場合に警告 | Phase2 |

**実効平均運賃**＝Σ（区分別構成比 × 区分別運賃 × (1−割引率)）を計算し、収入計算に使う。対キロ区間制の場合は、バス停別の推計乗車数と平均乗車距離（仮定値・変更可）から平均運賃を算出する。

### F-5 需要推計
#### 5.1 基本方式：勢圏人口ベースの原単位法（MVP）
```
年間利用者数(年度t) =
  Σ_バス停勢圏 Σ_年齢階層a [ 勢圏人口(a,t) × 外出率(a) × 1日トリップ数(a)
                              × バス分担率(a) × 路線捕捉率 ]
  × 運行サービス補正係数（便数・運行時間帯）
  × 運賃補正係数（運賃弾力性）
  × 立ち上がり係数(t)（運行開始直後の認知度不足による需要の低さ）
  × 年間運行日数換算
  ＋ 施設・観光等の外部需要（手入力）
```
- 勢圏人口：バス停勢圏とメッシュ人口の**面積按分**で算出。勢圏が重なる部分は二重計上しない
- 年齢階層：最低「0-14／15-64／65-74／75歳以上」
- 係数はすべて画面で変更可能。初期値と出典は係数マスタ（JSON）で管理し、出力物に記載

#### 5.1A 係数の決め方（v0.4追加）
- 外出率・1人1日あたりトリップ数・代表交通手段のバス分担率は、**国交省「全国都市交通特性調査（令和3年）」の集計データ**から、**都市類型（三大都市圏中心都市／三大都市圏周辺都市／地方中枢都市圏…等）×年齢階層×平日／休日**で取り込む。対象自治体から都市類型を自動判定し、該当する値を初期値とする（`data_build/` で e-Stat 公開の集計表をJSON化。値はコードに直書きしない）
- 令和7年度調査の結果が公表されたら差し替えられるよう、係数ファイルに調査年を持たせる
- 路線捕捉率：勢圏内で発生するバス利用のうち本路線を使う割合。**既存バス路線と勢圏が重なる場合は便数比で按分**、重ならない場合は1.0
- 根拠となる公的値が見つからない係数（立ち上がり係数、運賃弾力性など）は、**既定では効かせない**（立ち上がり=100%、弾力性=0）。ユーザーが値と出典を入力した場合のみ反映し、出力物に「ユーザー設定」と表示

#### 5.6 データ容量計画（v0.5追加）
GitHub Pagesは**公開サイト1GBまで・帯域は月100GB（目安）**、1ファイルは100MB未満。
| データ | 容量の目安の付け方 | 対策 |
|---|---|---|
| 道路網タイル | Phase0で東京都の実測値から全国分を推計 | バス通行可の道路に限定、交差点間の簡略化、座標の整数化、gzip圧縮 |

| バス停・路線 | 同上 | 必要な属性のみ |
| アプリ本体 | 数MB | − |

**1GBを超える見込みの場合**：データを地域ごとの**別リポジトリのGitHub Pages**（例：東日本・西日本）に分けて公開し、アプリから読み込む（いずれも無料）。分割しても使い方は変わらないようにする。

## 5. 非機能要件

| 区分 | 要件 |
|---|---|
| 構成 | **静的Webサイト**（HTML/JS/静的データのみ）。アプリ用のサーバ処理・DBは持たない |
| 認証 | なし |
| データ取扱い | ユーザーの入力データ・読み込んだファイルは**外部へ送信しない**。経路計算もブラウザ内で行う。外部通信は地図タイルと静的データの取得のみ（F-2-5g を使った場合を除く） |
| 検索除外 | 全ページに `<meta name="robots" content="noindex, nofollow">` を入れる（GitHub PagesはHTTPヘッダを設定できないため、metaタグのみ）。サイトマップは作らず、外部からリンクしない。※robots.txtでクロールを禁止すると noindex が読まれなくなるため、robots.txt では禁止しない。**URLを知っていれば誰でも見られる**ことは前提として受け入れる |
| 対象地域 | 全都道府県。都道府県境をまたぐルートに備え、表示範囲にかかる隣接県のデータも読み込む |
| アクセス解析 | 入れない（入れる場合も入力内容は送らない） |
| 通信 | HTTPSのみ |
| 性能 | 1シナリオ10年分の再計算が2秒以内（ブラウザ内）、地図表示3秒以内 |
| 再現性 | 同じプロジェクトファイル・同じツール版数なら、計算結果は必ず一致 |
| ライセンス表示 | 地理院タイル、国土数値情報（CC BY 4.0）、OpenStreetMap（「© OpenStreetMap contributors」を表示。加工した道路網データはODbLに従って公開）、参考実績データの出典を画面と出力物に表示 |
| 保守性 | 計算ロジックはUIから分離した純粋関数（TypeScript）とし、単体テスト必須 |
| 対応ブラウザ | Chrome / Edge 最新版 |

**ログインなしで公開することの注意点**：誰でもアクセスできるため、サイトに置くファイル（同梱データ・サンプルプロジェクト）には**社外秘の情報を入れない**。案件固有の情報はプロジェクトファイルにだけ持たせる。

## 6. 推奨技術構成（Claude Code向け）

| レイヤ | 推奨 | 理由 |
|---|---|---|
| フレームワーク | React + TypeScript + Vite（静的ビルド） | Claude Codeが得意。ビルド結果をそのまま静的ホスティングに置ける |
| 地図 | MapLibre GL JS | OSS・無償 |
| GIS計算 | Turf.js | 勢圏バッファ・面積按分をブラウザで計算 |
| グラフ | Recharts または ECharts | PNG出力が容易 |
| 入力検証 | Zod | プロジェクトファイルの形式チェックと型定義を共通化 |
| 一時保存 | IndexedDB（idb-keyval 等） | 自動一時保存 |
| Excel出力 | SheetJS または ExcelJS | ブラウザ内で生成 |
| GTFS読込 | JSZip＋CSVパーサ（Phase2） | ブラウザ内で処理 |
| 人口データ配信 | 都道府県別の事前加工済み静的ファイル（GeoJSON/FlatGeobuf 等） | サーバ処理不要 |
| 経路生成 | **ブラウザ内経路計算**：事前加工した道路網タイル（バス通行可の道路のみ・交差点間を1辺に簡略化・バイナリ形式）をWeb Workerに読み込み、双方向A*で計算。フォールバックは直線＋距離手入力 | サーバ不要・費用0円。OSRM公開デモサーバは非商用・毎秒1リクエストまでの制限があり業務利用できない。外部APIは共通キーを埋め込むと誰でも使えてしまう |
| 道路網の加工 | GitHub Actions（公開リポジトリは無料）で、Geofabrikの日本版OSMデータから都道府県ごとに道路網タイルを生成。定期実行（例：四半期） | 手元PCの負荷・手作業をなくす |
| ホスティング | **GitHub Pages**（GitHub Actionsでビルド・公開） | 無料。静的ファイルのみで動く構成と一致 |
| データ加工 | Python（geopandas、pdfplumber） | `data_build/` で人口・参考実績を事前加工 |

## 10. 受入基準（MVP）

1. 地図上で既存バス停を選択・新規追加し、ルートが描画される（経路APIが使えないときは直線＋距離手入力で続行できる）
2. 均一制・対キロ区間制それぞれで運賃表が自動生成され、手修正できる
3. 勢圏人口が年齢階層別に算出され、内訳を画面で確認できる
4. 開発計画（地点・年度・人数）を登録すると、該当年度以降の利用者数に反映される
5. 年度別の利用者数・運賃収入・その他収入・合計が表とグラフで表示される
6. 輸送力を超える需要の場合に警告が出て、頭打ちで計算される
7. 推計結果と参考実績（1日利用者数・1便あたり人数・平均運賃）が並べて表示される
8. **プロジェクトファイルを保存→ブラウザを閉じる→別PCで読込**で、入力と計算結果が完全に一致する
9. 不正なファイルを読み込むと、問題の項目が表示され、画面が壊れない
10. 開発者ツールで確認し、入力データが外部へ送信されていない（通信は地図タイル・静的データの取得のみ）
13. 東京都内の代表的な10区間で、経路が道路に沿い、一方通行・進入禁止を守っている（目視確認）
11. CSV（Excelで文字化けしない）、xlsx、PNGが出力でき、前提条件と出典が含まれる
12. 計算ロジックの単体テストが通る（手計算サンプルと一致）

## 13. 用語

| 用語 | 意味 |
|---|---|
| 勢圏 | バス停から徒歩で利用できるとみなす範囲（初期値300m） |
| 面積按分 | メッシュの人口を、勢圏と重なる面積の割合で配分する計算 |
| 分担率 | 全移動のうちバスが使われる割合 |
| 運賃弾力性 | 運賃が1%上がったときに利用者が何%減るかを示す係数 |
| 営業係数 | 100円の収入を得るのに必要な費用。100未満なら黒字 |
| 収支率 | 運賃収入÷運行経費 |
| GTFS-JP | バスの停留所・経路・時刻表を記述する国内標準のデータ形式 |
| プロジェクトファイル | 本ツールの入力内容一式を保存したJSONファイル（.busproj.json） |
