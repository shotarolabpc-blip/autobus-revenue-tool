# 受入確認（MVP）

要件定義書「10. 受入基準（MVP）」の各項目の確認方法です。自動テストで確かめられるものはテストの場所を、目視が必要なものは手順を書いています。

- 自動テスト（計算・データ）：`npm test`（Vitest）、`.venv\Scripts\python -m pytest -q data_build\tests`（Python）
- 自動テスト（画面の操作）：`npm run e2e`（Playwright。パソコンに入っている Chrome を使います。開発サーバーを自動で起動します）

## 目視確認の手順

### A. ルート（基準1・13）

1. 「プロジェクト」で新規作成し、「地図」画面を開く。
2. 「＋ バス停を追加」で3か所以上クリックして、ルートが道路に沿って引かれることを確かめる。
3. 次の10区間で、道路に沿っているか、一方通行・進入禁止を守っているか（逆走していないか）を地図で見る。区間は「道路が入り組んだ場所」「一方通行が多い場所」から選ぶ。
   例：①三鷹駅南口〜吉祥寺駅　②新宿駅西口〜都庁　③渋谷駅〜代々木公園　④東京駅丸の内〜有楽町駅　⑤浅草寺〜上野駅　⑥池袋駅東口〜サンシャイン60　⑦品川駅港南口〜天王洲アイル　⑧秋葉原駅〜御茶ノ水駅　⑨北千住駅〜牛田駅　⑩二子玉川駅〜用賀駅
4. 道路に沿わない区間があれば、区間の「経路」を「直線」に切り替え、「手修正」で距離を入れて続けられることを確かめる。
5. 経由点：ルートの線をドラッグして「この交差点を通る」形に直せること。「もう一度通るバス停」で、同じバス停を停車順に加えられること。

### B. 外部送信の確認（基準10）

1. ブラウザで開発者ツール（F12）を開き、「ネットワーク」タブを開く。「ログを保持」にチェックを入れる。
2. プロジェクトを作成し、バス停を置き、各画面を回って、「推計結果」でExcel・CSV・PNGを出力する。
3. 通信の一覧を見て、通信先が次の2つだけであることを確認する。
   - このサイト自身（`…github.io`、開発中は `localhost`）：画面・静的データ（`/data/…`）の取得
   - 地理院タイル（`cyberjapandata.gsi.go.jp`）：背景地図
4. 「メソッド」の列に `POST`・`PUT` がないこと（データを送る通信がないこと）を確認する。

### C. 出力（基準11）

1. 「推計結果」で「Excel（.xlsx）」を保存して開く。シートが「前提条件／運賃表／年度別推計／バス停別／参考実績比較／出典一覧」の6つあること。
2. どのシートの先頭にも「推計日時・プロジェクト・シナリオ・データ版数・出典・ツール版数」があること。
3. 「CSV：前提条件」などをExcelで開いて、文字化けしないこと。
4. 「前提条件」シートに、都市類型・係数の出典・0〜4歳が暫定である旨・運賃の目安と出典が載っていること。「出典一覧」に、地理院タイル・国土数値情報・OpenStreetMap・全国都市交通特性調査・車両スペックが載っていること。
5. グラフのPNGと、「地図」画面の「推計結果を重ねる」→「地図をPNGで保存」のPNGを開き、出典・シナリオ名・推計日時が画像の下に入っていること。

### D. 推計の確かめ方（桁感）

1. 「推計結果」の「計算の内訳」で、バス停ごとの勢圏人口が、地図のその場所の人口の感覚と大きく違わないか。
2. 1日の延べ乗車人員が、同じような規模の既存路線（コミュニティバスなど）と同じ桁か。「参考実績との比較」に実績を入れて見る。
3. 勢圏が既存のバス路線と重なっている場合は、画面に警告が出る。出たら「前提条件」の「路線捕捉率」を入れて、人数が下がること。

### 未実装

- **参考実績の同梱データ**（F-5-5）：都営バスの系統別収支などは、PDFの読み取りに人の確認が必要なため、まだ入っていません。いまは、手元の実績をCSV・手入力で追加する方式（F-5-8）だけです。
- **都市類型の自動判定は一部の市区町村だけ**（確認事項 Q4）：調査の対象都市の一覧にある東京都区部・稲城市・青梅市だけ自動判定し、それ以外は「全国計」を使って画面に明示しています。「前提条件」画面で選べます。
- **既存路線との重なりは警告のみ**（確認事項 Q5）：運行本数のデータがないため自動の按分はできず、路線捕捉率は手入力です。
- **東京都以外の都道府県のデータ**（人口・バス停・道路網）：作り方（`data_build`）はあり、都道府県コードを引数にする形ですが、生成と公開は東京都だけです（容量は `docs/capacity.md`）。
- **開発計画の場所を地図のクリックで指定する操作**（F-5-1）：いまは緯度・経度またはメッシュコードの入力です。
- 月別集計（F-6-5）、PDFレポート（F-8-6）、補正係数の自動算出（F-5-9）：要件定義書でも Phase2 です。
- Playwright の自動テストは、バス停の準備を開発用の入口から入れています。地図のクリック操作そのものは、上の目視確認で確かめます。

### 既知の注意

- 0〜4歳の係数は、調査の対象外のため暫定で5〜14歳の値を使っています（確認事項 Q2 が未決定）。画面と出力物に注意が出ます。
- 立ち上がり係数・運賃弾力性・運行サービス補正は、公的な根拠値がないため既定では効かせていません（入力したときだけ、出典つきで反映）。
- 楽観・悲観シナリオは、元のシナリオの入力を引き継ぎ、住民の需要だけを±%します（施設等の需要は変えません）。増減の%は、根拠のある値がないので、ご自身で決めて入れます。
- 公表前の年の祝日は推定値で運行日数を数えています（確認事項 Q12）。
- 対キロ区間制の平均運賃は、平均乗車距離を入力しない場合、「各バス停から先のバス停へ均等に降車する」という仮定で求めています（確認事項 Q10）。
